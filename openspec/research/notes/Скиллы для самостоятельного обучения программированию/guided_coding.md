# Скиллы для совместной учебной реализации

## Какие готовые скиллы ближе к направляющему режиму

### Takeaway
Три проверенных варианта содержат полезные механики, но каждый расходится с требованием пользователя: помогать реализовывать только отдельные части и отказывать в автоматическом выполнении всего задания. Это сравнение текстов инструкций, а не испытание их поведения.

### Cited Findings
- **socratic-code-mentor**, автор ogzhanolguncu: ученик реализует учебное ядро, агент самостоятельно делает остальное, включая тесты и инфраструктуру. Работа делится на уровни с проверяемым результатом. Агент перечитывает изменения и запускает тесты; следующий уровень начинается после исправления текущего. Есть лестница подсказок до выдачи кода. Однако просьба закончить за пользователя прямо переводит на выдачу кода; исправленный файл тоже допустим по просьбе. Это принципиальное расхождение с требованием не делать задание целиком. — [Оригинальный SKILL.md](https://gist.github.com/ogzhanolguncu/274e9974dc02942109ad70200f6d7b25)
- **algo-sensei**: основной файл выбирает режимы обучения, подсказок, ревью, интервью и распознавания алгоритмических паттернов. Запрещает полное решение без объяснения, но не запрещает полное решение вообще. В основной инструкции также присутствует необязательное предложение поставить звезду репозиторию с использованием отдельного помощника; это постороннее поведение для задачи пользователя. — [SKILL.md](https://raw.githubusercontent.com/karanb192/algo-sensei/main/SKILL.md)
- В **tutor-mode** из algo-sensei предлагается разбирать входы, примеры, паттерн, интуицию, затем переводить псевдокод в код по шагам и анализировать сложность. Шаблон ответа содержит готовую реализацию; ограничения одной согласованной частью задания нет. — [tutor-mode.md](https://raw.githubusercontent.com/karanb192/algo-sensei/main/modes/tutor-mode.md)
- В **hint-mode** из algo-sensei есть постепенное раскрытие вплоть до псевдокода, ожидание попытки ученика и помощь с синтаксисом. Это полезная модель для наводящего режима, но обязательный старт с первого уровня и запрет пропускать уровни плохо соответствуют отдельному быстрому режиму пользователя. — [hint-mode.md](https://raw.githubusercontent.com/karanb192/algo-sensei/main/modes/hint-mode.md)
- **engineering-growth-mentor**: предлагает сначала искать аналог в существующем проекте, показывать подход с альтернативами, затем реализовывать согласованный план и проверять результат. Обучение привязано к реальным изменениям, без постоянных экзаменов; небольшие самостоятельные задания факультативны. При этом скилл прямо разрешает прямой ответ по просьбе и не должен блокировать запрошенный результат. Отдельный запрет полного решения учебного задания отсутствует. Кроме того, до одобрения плана он запрещает потенциально изменяющие состояние команды, включая некоторые тесты и сборки, что потребует адаптации к пожеланию пользователя активно запускать проверки. — [SKILL.md](https://raw.githubusercontent.com/EDM115/skills/master/skills/engineering-growth-mentor/SKILL.md)

### Inferences
- Самая полезная заготовка для совместной реализации — механика уровней и проверок socratic-code-mentor. Её следует адаптировать концептуально, убрав автоматическое написание всей вспомогательной части и переход к полному решению по просьбе.
- Для поиска переносимых методов полезнее алгоритмическая часть algo-sensei: распознавание паттерна, объяснение применимости, сложности и компромиссов. Его ориентированность на DSA/LeetCode уже, чем всё учебное программирование.
- Для работы с реальным репозиторием полезен engineering-growth-mentor: опора на существующие решения и предметная проверка понимания. Целиком переносить его процесс согласований не требуется.

### Gaps
- Наличие четырёх сочетаний «наводящий/направляющий × обычный/быстрый», явного вызова только через `$` и неизменного отказа выполнять всё задание целиком не подтверждено ни у одного из трёх проверенных кандидатов. Это не утверждение, что такого решения вообще нет в интернете.
- Не проводились установка, запуск, сравнительные учебные сессии или оценка надёжности соблюдения инструкций.

## Можно ли повторно использовать найденное

### Takeaway
У двух репозиториев подтверждена MIT-лицензия; у оригинального gist лицензия на просмотренной странице не указана. Для небольших персональных скиллов рациональнее написать собственные инструкции по согласованным требованиям, используя найденные механики как ориентир.

### Cited Findings
- algo-sensei опубликован под MIT; при копировании существенных частей сохраняются уведомление об авторских правах и условия лицензии. — [LICENSE](https://raw.githubusercontent.com/karanb192/algo-sensei/main/LICENSE)
- Репозиторий EDM115/skills, содержащий engineering-growth-mentor, опубликован под MIT с аналогичным требованием сохранения уведомления. — [LICENSE](https://raw.githubusercontent.com/EDM115/skills/master/LICENSE)
- На просмотренной странице оригинального socratic-code-mentor присутствует один файл SKILL.md; отдельное лицензионное уведомление в нём не обнаружено. Это описание просмотренного источника, не юридический вывод. — [Оригинальный gist](https://gist.github.com/ogzhanolguncu/274e9974dc02942109ad70200f6d7b25)

### Inferences
- Смысл создавать персональные скиллы есть: отличие не в изобретении нового метода обучения, а в точном правиле авторства, ограничении размера реализации и двух темпах без снятия учебных ограничений.
- Прямое копирование большого набора режимов, дополнительных скриптов и необязательных интеграций добавит больше настройки, чем нужно четырём коротким персональным скиллам.

### Gaps
- Юридическая проверка лицензий и лицензий всех вспомогательных файлов не проводилась. Полезные идеи можно описать самостоятельно, не копируя текст неизвестного лицензионного статуса.
