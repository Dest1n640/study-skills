# Экосистема обучения программированию через скиллы

## Какие подходы уже реализованы

### Takeaway
За пределами первоначальных четырёх кандидатов найдены ещё семь содержательно разных реализаций: обучение модели исполнения, чтение чужого проекта, локальный практикум, навигация при реализации, многоролевой наставник, курсовой тьютор и строительство реальных инструментов. Сам по себе «Socratic tutor для coding agent» уже не редкий замысел; различать продукты нужно по конкретному поведению.

### Cited Findings

| Пример и первичный источник | Механика, границы и отличие от замысла пользователя |
|---|---|
| **cdmorozov / programming-tutor** — [SKILL.md](https://raw.githubusercontent.com/cdmorozov/claude-tutors/main/programming-tutor/SKILL.md) | Пять режимов: concept/problem/debug/review/path. На концептуальный вопрос отвечает сразу, без обязательной проверки понимания; активную задачу ведёт по лестнице подсказок. Отладка учит наблюдать, формулировать гипотезу и локализовать расхождение. Предлагает перенос через изменение требования, реконструкцию и прогноз результата. Review содержит прямые выводы и проверку крайних случаев. Существенный escape hatch: после настойчивого требования разрешает код с объяснением и задачей на перенос. Подходит как образец адаптивного объяснения, но не абсолютного строгого запрета. |
| **Shuangmu004 / learning-open-source-projects** — [SKILL.md](https://github.com/Shuangmu004/Learn-Skill/blob/main/learning-open-source-projects/SKILL.md) | Для понимания незнакомого репозитория: orient, trace, explain, debug, contribute, assess. Требует реальных файлов, тестов и runtime-вывода, различает подтверждённое/выведенное/неизвестное. Цикл predict → inspect → explain → experiment → recall, одна вертикаль или концепция. Объяснение, review и диагностика read-only; реализация возможна после установления текущего поведения и способа проверки. Это ниша опытных разработчиков, осваивающих чужой код, а не только начинающих. Текст не даёт абсолютного запрета полных решений, и отдельные reference-файлы в этой проверке не прочитаны. |
| **zoubingwu / learn-by-doing** — [SKILL.md](https://raw.githubusercontent.com/zoubingwu/learn-by-doing-skill/main/skills/learn-by-doing/SKILL.md) | Генерирует полный staged roadmap, все запланированные skeleton+tests+README, запускает проверки, отслеживает состояние и dashboard. Ученик пишет ядро реализации. Правки требуют прямого разрешения; инструментальные проверки входят в процесс. Это скорее генератор персонального локального практикума, чем компактный помощник при существующем задании. |
| **snack-boomz / navigator** — [SKILL.md](https://github.com/snack-boomz/navigator/blob/main/SKILL.md) | Человек реализует, агент действует как старший разработчик рядом: обозначает решения и компромиссы, замечает ошибки, объясняет механику, коротко возвращает ход человеку. Примеры преимущественно React/hooks. Есть настройка темпа по демонстрируемому пониманию. Внутреннее напряжение: запрещает готовые компоненты «даже если просят», но затем требует немедленно выйти в генерацию по «just write it / finish it». Это режим с простым выходом, а не постоянное правило не решать всё. Явной обязательной процедуры запуска тестов в основном файле нет. |
| **davejpeters / opencode-mentor, core** — [SKILL.md](https://github.com/davejpeters/opencode-mentor/blob/main/skills/core/SKILL.md) | Общее ядро mentor/reviewer/architect/drill-instructor. Диагностика → объяснение → практика → оценка → рефлексия → следующий шаг. Подстраивает уровень по состоянию ученика, требует оценивать присланный код и проверять тестами, typecheck, lint, build либо инспекцией. Mentor обычно не редактирует; reviewer не переписывает по умолчанию; нет универсального безусловного запрета кода. Польза — постепенное уменьшение поддержки и работа с опытом ученика; цена — зависимость от ролей, оркестратора и специальных tutor_* инструментов. |
| **benrosche / socratic-tutor** — [SKILL.md](https://raw.githubusercontent.com/benrosche/socratic-tutor/master/templates/lab-repo/.posit/assistant/skills/tutor/SKILL.md) | Курсовой tutor для notebook-задач с `#| task:`. Сервер даёт скрытое эталонное решение и уровень подсказки, счётчик сохраняется между чатами. Полное решение запрещено; разрешены маленькие локальные примеры 1–3 строки и скелеты. Помощь: диагноз, вопрос, подсказка, следующий шаг. При недоступном сервере продолжает по коду ученика и сообщает ограничение. Это близко guide с запретом целого задания, но привязано к учебной инфраструктуре и не разрешает автоматически любую частичную реализацию. |
| **ogzhanolguncu / socratic-code-mentor** — [Оригинальный gist с SKILL.md](https://gist.github.com/ogzhanolguncu/274e9974dc02942109ad70200f6d7b25) | Проектное обучение через копии реальных инструментов: Redis, git, parser. Challenge: ученик пишет всё; mentor: ученик пишет обучающее ядро, агент — wiring, тесты и окружение. Проверяет настоящий код, тесты и done-check, даёт наблюдаемый результат, сравнение с oracle или реальным инструментом. Подсказки усиливаются до кода; прямое «do it» сразу разрешает последнюю ступень. Отдельного объяснения обратно не требует. Это сильный аналог комфортного наставника, но core/non-core деление и escape hatch отличаются от требований пользователя. |

- В дополнительной политике learn-by-doing прямо разрешено полное решение по прямому запросу или разрешению ремонта. Лестница: концепция → место в коде → подход; после прохождения проверки — краткое обобщение и следующая задача. — [feedback-policy.md](https://raw.githubusercontent.com/zoubingwu/learn-by-doing-skill/main/skills/learn-by-doing/references/feedback-policy.md).
- OpenCode Mentor распространяется как конфигурация с агентами, плагинами, инструментами, Bun и глобальной настройкой; README предупреждает о несовместимости с OpenCode v2 на проверенной странице. Поэтому это не эквивалент маленького переносимого пакета из четырёх файлов. — [README](https://github.com/davejpeters/opencode-mentor).

### Inferences
- Представительные зоны уже заняты: подсказки к алгоритмам; guided debugging; проектное обучение; чтение чужого кода; персональный roadmap; профили и прогресс. Нельзя честно позиционировать собственный продукт как первый учебный скилл, первого Socratic coding tutor или уникальный запрет писать за ученика.
- Строгий hint, где подробный псевдокод относится только к текущему шагу, имеет более точную границу, чем обычное «no spoilers». Но уникальность этой границы во всём интернете не доказана.
- Более содержательный продуктовый акцент — четыре заранее понятных режима, явное право на код, одинаковая работа с реальным проектом/проверками, понятные переносимые методы и адаптация к опыту. Это возможное удобство упаковки и предсказуемость, а не доказанная новая педагогика.

### Gaps
- Обзор репрезентативный, не полный каталог. Отсутствие точного совпадения в проверенной выборке не устанавливает незанятую нишу или спрос.
- Читались исходные инструкции, но поведение скиллов на моделях не испытывалось; найденные обещания не равны измеренным результатам обучения.
- Основной файл Shuangmu004 просмотрен целиком, но reference `contribute.md` получить не удалось; детали права агента в этой ветке остаются непроверенными.

## Как совместить понимание и отсутствие обязательных остановок в guide

### Takeaway
Пользователь окончательно уточнил guide: объяснять по ходу работы; проверять понимание только по его просьбе. Обязательные вопросы, остановки, квизы и проверка после каждой части не нужны. Инструментальная проверка корректности кода остаётся отдельной обязанностью, а понимание без свидетельств не объявляется установленным.

### Cited Findings
- Programming Tutor различает самостоятельные объяснения без вопросов и практику с прогнозом/переносом; проверка после концептуального объяснения opt-in. Это показывает существующий способ избежать обязательных пауз при каждом объяснении. — [SKILL.md](https://raw.githubusercontent.com/cdmorozov/claude-tutors/main/programming-tutor/SKILL.md).
- Socratic Code Mentor на последней ступени прямо выдаёт локальные строки и краткое объяснение, не требуя объяснения обратно; одновременно сохраняет инструментальные проверки. — [SKILL.md](https://gist.github.com/ogzhanolguncu/274e9974dc02942109ad70200f6d7b25).
- Learning Open Source Projects связывает проверенное понимание с прогнозом, экспериментом и пересказом потока/инварианта; это более требовательный режим участия, чем непрерывное чтение готового решения. — [SKILL.md](https://github.com/Shuangmu004/Learn-Skill/blob/main/learning-open-source-projects/SKILL.md).

### Inferences
- **Согласованная граница guide:** объяснять решение части по ходу; прогнозы, вариации и вопросы для проверки понимания применять только по запросу ученика. Нельзя объявлять понимание установленным из молчания или успешных тестов.
- В guide границу «не решить всё вслепую» нужно определять по объёму и намерению запроса: видеть всё задание для планирования допустимо; автоматически реализовать все его части подряд по одному общему «сделай» — нет. Отсутствие обязательной паузы не означает неограниченную автономную реализацию.
- Normal/fast стоит различать глубиной объяснений и прямотой подсказки; это не повод вводить проверку понимания в guide без просьбы пользователя.

### Gaps
- Не определено, как пользователь хочет разрешать неоднозначность: «продолжай» означает следующую часть реализации или дальнейшее объяснение. Не следует молча превращать это в обязательные подтверждения каждого шага.
- Доказательств эффективности именно четырёх режимов из просмотренных репозиториев нет.

## Что учитывать для публичного пакета с короткой установкой

### Takeaway
Короткая установка и переносимый Markdown уже встречаются. Для нового GitHub-проекта разумно подтвердить ценность наблюдаемым поведением, а не количеством правил или обещанием уникальности.

### Cited Findings
- learn-by-doing уже документирует `npx skills add zoubingwu/learn-by-doing-skill --skill learn-by-doing` и явный `$learn-by-doing`; это пример короткой установки и отделения installable payload от файлов разработки. — [README](https://github.com/zoubingwu/learn-by-doing-skill).
- Socratic Code Mentor распространяется одним gist-файлом с указанием пути `~/.claude/skills/socratic-code-mentor/SKILL.md`. — [Gist](https://gist.github.com/ogzhanolguncu/274e9974dc02942109ad70200f6d7b25).
- programming-tutor имеет MIT LICENSE с copyright Artem, 2026. — [LICENSE](https://raw.githubusercontent.com/cdmorozov/claude-tutors/main/LICENSE).
- benrosche/socratic-tutor имеет MIT LICENSE с copyright Ben Rosche, 2026. — [LICENSE.md](https://raw.githubusercontent.com/benrosche/socratic-tutor/master/LICENSE.md).

### Inferences
- Для отличия от соседей полезны несколько публичных примеров диалога и проверки: требование целого решения, просьба написать часть, ошибка ученика, fast без нарушения границ, переход от новичка к опытному. Эти проверки стоит оценивать по поведению, а не поиску точных фраз в SKILL.md.
- Поддержка пользователей любого опыта требует менять глубину объяснений, а не фиксировать уровень beginner по умолчанию. Для публикации пользователь хочет переносимость на skill-capable agents, в первую очередь Codex/Claude; это цель проекта, не подтверждённая совместимость четырёх ещё не написанных скиллов.
- Первую версию можно выпустить четырьмя небольшими самостоятельно понятными скиллами без платформы профилей, dashboard, серверов и валюты. Общие формулировки можно поддерживать последующей простой сборкой, если появится реальная необходимость; инфраструктура не нужна для проверки идеи.
- Сравнение с существующим programming-tutor и TuTor на одних заданиях даст более убедительный ответ «зачем этот проект», чем заявление о незанятой нише.

### Gaps
- Лицензии остальных пяти новых примеров не установлены в этой проверке. Публичный исходный файл не означает автоматически разрешение копировать его существенный текст в свой продукт.
- Установки и совместимость с клиентами не проверялись. Команды выше — документированные авторами примеры, не наша рекомендация выполнить их без проверки.
- Не исследовались спрос, удержание пользователей и экономический смысл продукта; по исходным файлам их определить нельзя.
